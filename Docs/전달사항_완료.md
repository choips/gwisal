# 귀살 — 처리 완료된 전달 사항 (보관)

> `개발현황.md`의 "📬 전달 사항"에서 처리가 끝난 항목을 옮겨 두는 곳입니다. 평소에는 읽을 필요가 없습니다.

**[전달-01] 🔴 Cursor의 마크다운 자동 서식 끄기** (2026-10-14) — ✅ 처리 완료 2026-10-15
- 왜: Cursor가 `.md` 파일을 저장할 때 표 칸 맞춤을 자동으로 바꾸면서, `개발현황.md`가 한 번에 1,600줄씩 바뀌고 번호 목록이 표 안으로 빨려 들어가거나 "5."가 "1."로 바뀐 곳이 생겼습니다 (2026-10-13 "한글 깨짐 복구" 커밋). Claude와 Cursor가 같은 문서를 고칠 때 충돌이 날 위험도 커집니다.
- 할 일: 사용자가 직접 끌 수 있게 Cursor 설정(Ctrl + ,)에서 마크다운 파일의 저장 시 자동 서식(format on save)을 끄는 방법을 단계별로 안내. 프로젝트의 `.vscode/settings.json`에 `"[markdown]": { "editor.formatOnSave": false }`를 넣는 방법도 함께 제안.
- (깨진 두 곳은 2026-10-14 문서 나누기 때 Claude가 `Docs/기획/07_아트_성능_모바일_출시.md`에서 이미 고침)
- 언제: 다음 작업을 시작하기 전에 가장 먼저.
- 완료 조건: `개발현황.md`를 저장해도 고친 줄 말고는 바뀌지 않음 (`git diff`로 확인).
- **처리 결과 (Cursor)**:
  - 자동 서식 설정(`formatOnSave`)은 원래 꺼져 있었고 마크다운 확장도 없음. 진짜 원인은 **Cursor 내장 마크다운 편집기의 꾸민 화면(Rich)** — 파일마다 모드를 기억하며(기본은 글자 화면), 예전 문서의 "Ctrl + Shift + V = 미리보기" 안내로 `개발현황.md`가 꾸민 화면으로 바뀌어 있었음. 꾸민 화면은 저장할 때(스스로 저장하기도 함) 문서를 처음부터 다시 써서 번호 목록 `0.`→`1.`, 굵은 글씨 범위, 표, 빈 줄을 바꿈. 꾸민 화면 안에서는 `Ctrl + Shift + V`가 모드 전환이 아니라 붙여넣기로 동작.
  - 조치: 탭 오른쪽 클릭 → **Edit Markdown**으로 글자 화면 전환(파일마다 기억), `.vscode/settings.json`에 마크다운 서식 끄기·`*.md` 기본 편집기 지정(Git 제외 폴더라 이 PC에만), `개발현황.md` 사용법 문장과 "9. 꼭 기억할 것"에 주의 추가.
  - 확인: 글자 화면에서 한 줄 고쳐 저장 → `git diff --stat` 1줄만 바뀜.
