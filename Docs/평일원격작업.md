# 평일 낮 원격 작업 (PC Claude Code + 휴대폰)

> 2026-10-18 사용자 결정. 출근 전에 집 PC에서 Claude Code를 켜 두고, 회사에서 휴대폰 Claude 앱으로 구현을 지시합니다. 퇴근 후 밤에 그날 작업을 Unity에서 테스트합니다.
> 이 파일은 처음 설정할 때와 규칙이 헷갈릴 때만 읽습니다.

---

## 1. 누가 언제 무엇을

| 언제 | 어디서 | 누가 | 하는 일 |
|---|---|---|---|
| 평일 낮 (기획) | 휴대폰 → 클라우드 Claude Code | Claude | 기획 문서·엑셀·📬 전달 사항 정리, `main`에 바로 푸시 (지금과 같음) |
| 평일 낮 (구현) | 휴대폰 → **집 PC의 Claude Code** (Remote Control) | Claude | 코드 작성, 컴파일 확인, 그날 브랜치에 커밋, 밤 테스트 목록 작성 |
| 평일 밤 | 집 PC | 사용자 + Cursor | 밤 테스트 목록대로 Unity 테스트 → 고칠 것은 Cursor가 고침 → 통과하면 `main`에 합치기 |
| 주말 | 집 PC | 사용자 + Cursor | 지금처럼 구현·테스트 |

- 구분하는 법: Claude Code가 **Windows(집 PC)에서 돌고 있으면 평일 구현 모드**, 클라우드(Linux)에서 돌고 있으면 기획 모드입니다.

## 2. 처음 한 번만 하는 설정 (PC 앞에서)

1. **Claude Code 설치** — PowerShell을 열고 아래 한 줄을 실행합니다.
   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```
   - 설치가 끝나면 PowerShell을 닫았다가 다시 열고 `claude --version`을 입력해 버전이 나오는지 확인합니다.
   - 설치 방법은 바뀔 수 있습니다. 안 되면 https://code.claude.com/docs 의 설치 안내를 따릅니다.
2. **로그인** — 프로젝트 폴더로 이동한 뒤 `claude`를 입력하고, 안내에 따라 지금 쓰는 Claude 계정으로 로그인합니다. 로그인되면 `/exit`로 나옵니다.
   ```powershell
   cd "프로젝트 폴더 경로"   # 예: cd "D:\Unity\gwisal"
   claude
   ```
3. **PC가 잠들지 않게** — Windows 설정 → 시스템 → 전원(또는 "전원 및 배터리") → "화면 및 절전"에서 **절전 모드 전환을 "안 함"**으로 바꿉니다. 화면 끄기는 켜 둬도 괜찮습니다.
4. **Windows 업데이트 재시작 막기** — 설정 → Windows 업데이트 → 고급 옵션 → **사용 시간**을 "수동"으로 하고 출근~퇴근 시간(예: 8시~23시)을 넣습니다. 이 시간에는 업데이트 때문에 PC가 저절로 재시작하지 않습니다.
5. **Unity 경로 확인** — 파일 탐색기에서 `C:\Program Files\Unity\Hub\Editor\6000.2.0f1\Editor\Unity.exe`가 있는지 봅니다. 다른 곳에 있으면 그 경로를 Claude에게 알려 줍니다 (Claude가 이 문서 "4. 컴파일 확인"의 경로를 고칩니다).

## 3. 매일 하는 순서

### 출근 전 (PC 앞, 2분)

**① Unity 에디터 닫기**
- Unity 창 위 메뉴 **File → Exit**를 누릅니다 (또는 창 오른쪽 위 X). "저장할까요?"가 나오면 **Save**를 누릅니다.
- 왜: Unity가 켜져 있으면 Claude가 컴파일 확인을 할 수 없습니다 (같은 프로젝트는 Unity 하나만 열 수 있음).
- Unity Hub와 Cursor는 켜 두든 닫든 상관없습니다.
- 확실히 꺼졌는지 보려면: `Ctrl + Shift + Esc`(작업 관리자) → 목록에 **Unity**가 없으면 됩니다.

**② 프로젝트 폴더에서 PowerShell 열기** (둘 중 하나)
- 쉬운 방법: 파일 탐색기에서 프로젝트 폴더(`Assets`·`Docs`·`개발현황.md`가 보이는 폴더)를 엽니다 → 위쪽 **주소 표시줄**을 클릭 → 글자를 지우고 `powershell` 입력 → `Enter`. 그 폴더에서 PowerShell이 열립니다.
- 또는: 프로젝트 폴더 안 빈 곳에서 마우스 오른쪽 클릭 → **터미널에서 열기**.
- 맞게 열렸는지 확인: 줄 앞에 `PS D:\...\gwisal>`처럼 프로젝트 폴더 경로가 보이면 됩니다.

**③ 원격 연결 켜기**
- PowerShell에 아래를 입력하고 `Enter`를 누릅니다.
  ```powershell
  claude remote-control
  ```
- 처음에는 질문이 나옵니다 (모두 **영어 입력 상태**에서):
  - `Trust F:\UnityWorkspace\귀살? [y/N]` → `y` 입력 후 `Enter` (처음 한 번만)
  - `Enable Remote Control? (y/n)` → `y`
  - `Spawn mode ... Choose [1/2]` → **`1`** (same-dir) 후 `Enter`
- 반드시 **PowerShell 창**에서 실행합니다 (검은 명령 프롬프트 창에서는 `y`가 안 눌림).
- 연결되었다는 안내와 함께 링크(또는 QR 코드)가 나오면 준비가 끝난 것입니다.
- `claude`를 찾을 수 없다는 빨간 글씨가 나오면 설치가 안 된 것입니다 → "2. 처음 한 번만 하는 설정"의 1번을 다시 합니다.

**④ 휴대폰에서 확인 (출근 전에 꼭)**
- 휴대폰 Claude 앱 → **Code** → 세션 목록에 이 PC 세션(PC 이름이나 `gwisal` 폴더 이름)이 보이는지 봅니다. 안 보이면 화면에 나온 QR 코드를 휴대폰 카메라로 찍어 엽니다.
- 열어서 `지금 어느 폴더야?`라고 보내 봅니다. 프로젝트 폴더 경로로 대답하면 성공입니다.

**⑤ 그대로 두고 출근**
- PowerShell 창은 **닫지 않습니다.** 작업 표시줄로 내려 두는 것(최소화)은 괜찮습니다.
- 창 안에서 `Ctrl + C`를 누르면 연결이 끊기니 누르지 않습니다.
- 화면 잠금(`Windows + L`)이나 모니터 끄기는 괜찮습니다. **절전 모드만 안 됩니다** ("2. 처음 한 번만 하는 설정" 3번).

**더 편하게: 바탕 화면에 "출근" 아이콘 만들기 (한 번만)**
- **먼저 확장자를 보이게** 합니다: 파일 탐색기 위쪽 **보기 → 표시 → 파일 확장명**에 체크 (Windows 10은 **보기** 탭 → **파일 확장명** 체크). 이걸 안 켜면 이름을 `출근.bat`으로 바꿔도 실제로는 `출근.bat.txt`가 됩니다.
- 바탕 화면 빈 곳 오른쪽 클릭 → 새로 만들기 → 텍스트 문서 → 이름 `새 텍스트 문서.txt`를 **`.txt`까지 모두 지우고** `출근.bat`으로 바꿉니다 (확장자를 바꿀지 물으면 **예**). 아이콘이 톱니바퀴 모양으로 바뀌면 성공입니다.
- `출근.bat`을 오른쪽 클릭 → **편집**(Windows 11은 "추가 옵션 표시 → 편집")으로 열고 아래를 붙여 넣은 뒤 저장합니다. 셋째 줄의 경로는 내 프로젝트 폴더 경로로 바꿉니다.
  ```bat
  @echo off
  chcp 65001 > nul
  cd /d "F:\UnityWorkspace\귀살"
  start "" powershell -NoExit -Command "claude remote-control --spawn=same-dir"
  ```
  - 더블클릭하면 파란 PowerShell 창이 새로 열립니다. **검은 명령 프롬프트 창에서 바로 `claude`를 실행하면 `Enable Remote Control? (y/n)`에서 `y`가 안 눌리는 문제가 있어서**(2026-10-18 확인) PowerShell 창으로 엽니다.
  - `chcp 65001` 줄을 빼면 한글 폴더 이름(`귀살`)을 못 읽어서 폴더 이동에 실패하고 **바탕 화면에서** 연결됩니다 (2026-10-18 확인). 연결 화면 첫 줄이 `Connected · 귀살`이어야 맞고, `바탕 화면`이면 `Ctrl + C`로 끄고 파일 내용을 확인합니다.
  - `--spawn=same-dir`: 원격 세션이 **이 폴더에서 바로** 작업합니다 (Spawn mode 질문에서 `1`과 같음). `2`(worktree)는 세션마다 폴더 복사본을 따로 만들어서, Unity가 그 복사본마다 Library를 새로 만들고(오래 걸림) 밤에 여는 프로젝트 폴더에 작업이 바로 보이지 않으므로 쓰지 않습니다.
- 다음부터는 Unity를 닫고 **`출근.bat`을 더블클릭**하면 ②③이 한 번에 됩니다. 그다음 ④만 확인하고 출근합니다.

**퇴근 후 끄기**
- 파란 PowerShell 창을 클릭하고 `Ctrl + C`를 누르거나 창을 닫으면 원격 연결이 끝납니다. 그다음 Unity를 열고 밤 테스트를 합니다.
- PC는 계속 켜 둬도 되지만, **PowerShell 창은 매일 밤 끄고 아침에 `출근.bat`으로 새로 켭니다.** 켜 둔 채 Cursor로 작업하면 휴대폰에서 실수로 보낸 지시 때문에 같은 폴더를 둘이 동시에 고칠 수 있고, 하루 대화가 다음 날까지 이어지면 길어져서 흐려집니다.
- 퇴근 후 프로젝트 폴더는 그날 브랜치(`daily/...`)에 있습니다 → 그대로 밤 테스트를 합니다. 밤 테스트 없이 다른 작업부터 하려면 Cursor에게 먼저 `main`으로 바꾸라고 합니다.

### 회사에서 (휴대폰)
- 그 PC 세션을 열고 지시합니다. 예: `작업 시작하자. 전달-03 2단계 진행`
- Claude가 파일 수정·명령 실행 허락을 물으면 휴대폰에서 허락합니다.
- 하루에 **1~2단계**만 시킵니다. 끝나면 `오늘은 여기까지` 또는 `작업 종료`라고 하면 Claude가 정리합니다 (밤 테스트 목록·주차 메모·변경이력 → 커밋·푸시).

### 퇴근 후 (PC 앞)
1. Unity를 열고, `개발현황.md` "2. 지금 진행 중"의 **"🌙 밤 테스트"** 목록을 위에서부터 따라 합니다.
2. Cursor에게 `밤 테스트하자`라고 하면, Cursor가 목록을 읽고 함께 진행합니다.
3. 문제가 있으면 Cursor가 같은 브랜치에서 고칩니다. 모두 통과하면 Cursor가 `main`에 합치고 푸시합니다.

## 4. 평일 구현 때 Claude(PC)가 지킬 것

### 시작할 때
- `git fetch origin` 후, 오늘 브랜치가 없으면 최신 `origin/main`에서 **`daily/YYYY-MM-DD`** 브랜치를 만듭니다 (예: `daily/2026-10-20`). 있으면 그 브랜치로 바꾸고 `origin/main`을 합칩니다.
- 전날 브랜치가 아직 `main`에 안 합쳐졌으면(밤 테스트를 못 한 날) 새 브랜치를 만들지 않고 **그 브랜치에서 이어서** 작업합니다. 테스트 안 한 작업이 3단계 넘게 쌓이면 새 단계를 시작하지 말고 사용자에게 알립니다.
- `개발현황.md`의 📬 전달 사항과 주차 메모를 먼저 읽습니다 (Cursor와 같은 규칙: `.cursor/rules/dev-status.mdc`, `개발현황.md` "0. AI 작업 안내", "9. 꼭 기억할 것").

### 작업할 때
- **하루 1~2단계.** 단계 하나가 끝날 때마다 컴파일 확인 → 커밋 → 푸시(`git push -u origin daily/...`).
- **사람이 에디터에서 해야 하는 일은 피합니다.** 씬·프리팹 파일(`.unity`, `.prefab`)을 글자로 직접 고치지 않습니다. 컴포넌트는 가능하면 코드에서 자동으로 붙이고(예: `PlayerEvade`), 꼭 에디터 작업이 필요하면 밤 테스트 목록에 "에디터 설정" 단계로 적습니다.
- 플레이해 봐야 아는 것(손맛·배치·밸런스)은 추측으로 확정하지 않고 밤 테스트 항목으로 남깁니다.
- 기획(`Docs/기획/`)은 고치지 않습니다. 기획 문제가 보이면 사용자에게 묻습니다.

### 컴파일 확인 (단계마다, 커밋 전에 꼭)
Unity를 화면 없이 실행해 컴파일만 하고 끕니다. 처음에는 몇 분 걸릴 수 있습니다.
```powershell
& "C:\Program Files\Unity\Hub\Editor\6000.2.0f1\Editor\Unity.exe" -batchmode -nographics -quit -projectPath (Get-Location).Path -logFile "$PWD\Logs\batch_compile.log"
echo $LASTEXITCODE
Select-String -Path "Logs\batch_compile.log" -Pattern "error CS" | Select-Object -First 20
```
- `$LASTEXITCODE`가 0이 아니거나 `error CS`가 나오면 고치고 다시 확인합니다. 에러가 남은 채로 커밋하지 않습니다.
- "another Unity instance is running" 같은 말이 나오면 Unity 에디터가 켜져 있는 것입니다 → 사용자에게 알리고, 컴파일 확인 없이 커밋했다고 밤 테스트 목록에 적습니다.
- 새 `.cs` 파일을 만들면 이 실행 때 `.meta` 파일이 생깁니다 → **`.meta`도 함께 커밋**합니다.
- `Logs/`는 Git에서 빠져 있으므로 로그 파일은 커밋되지 않습니다.

### 마칠 때 ("오늘은 여기까지" / "작업 종료")
1. `개발현황.md` "2. 지금 진행 중"의 **"🌙 밤 테스트"**를 씁니다 (아래 형식).
2. 진행 중 체크리스트(코드 `[x]`, 테스트 `[ ]`)와 주차 메모를 갱신하고, `Docs/변경이력.md`에 한 줄 추가합니다.
3. 커밋·푸시하고 휴대폰에 "오늘 한 일 / 밤 테스트 N개"를 짧게 알립니다.

### 🌙 밤 테스트 형식
```
### 🌙 밤 테스트 (daily/2026-10-20 — 아직 main에 안 합침)
> 평일 낮에 Claude가 PC에서 작업한 것. 위에서부터 순서대로. 통과하면 Cursor가 main에 합치고 이 섹션을 비웁니다.
- 오늘 한 일: [전달-03] 2단계 — 깨진 세이브를 .bak으로 복구 (`abc1234`)
- 컴파일 확인: 통과
- [ ] (에디터 설정) 없음
- [ ] 테스트 1: 플레이 → S로 저장 → 종료 → … → 기대 결과: "…" 알림이 뜸
- [ ] 테스트 2: …
- 잘 모르겠는 것: (Claude가 판단 못 해 사용자가 봐 줘야 할 것)
```

## 5. 밤에 Cursor가 할 일
- `밤 테스트하자` 또는 새 채팅을 열면, "🌙 밤 테스트" 섹션이 있는지 먼저 확인하고 알립니다.
- 그 브랜치(`daily/...`)로 바꾼 상태인지 확인한 뒤(`git status`), 사용자와 목록을 하나씩 진행합니다.
- 문제가 있으면 **같은 브랜치에서** 고치고 다시 테스트합니다.
- 모두 통과하면: 진행 중 체크리스트에 테스트 `[x]` → `main`으로 바꾸고 `git pull` → `git merge daily/...` → 푸시 → "🌙 밤 테스트" 섹션을 "(없음)"으로 비우고 커밋·푸시. 다 합친 `daily/...` 브랜치는 지워도 됩니다.
- 그날 테스트를 다 못 하면 브랜치를 그대로 두고, 섹션에 어디까지 했는지 적습니다. 다음 날 Claude가 그 브랜치에서 이어갑니다.
