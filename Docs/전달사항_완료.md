# 귀살 — 처리 완료된 전달 사항 (보관)

> `개발현황.md`의 "📬 전달 사항"에서 처리가 끝난 항목을 옮겨 두는 곳입니다. 평소에는 읽을 필요가 없습니다.

**[전달-01] 🔴 Cursor의 마크다운 자동 서식 끄기** (2026-10-14) — ✅ 처리 완료 2026-10-15
- 왜: Cursor가 `.md` 파일을 저장할 때 표 칸 맞춤을 자동으로 바꾸면서, `개발현황.md`가 한 번에 1,600줄씩 바뀌고 번호 목록이 표 안으로 빨려 들어가거나 "5."가 "1."로 바뀐 곳이 생겼습니다 (2026-10-13 "한글 깨짐 복구" 커밋). Claude와 Cursor가 같은 문서를 고칠 때 충돌이 날 위험도 커집니다.
- 할 일: 사용자가 직접 끌 수 있게 Cursor 설정(Ctrl + ,)에서 마크다운 파일의 저장 시 자동 서식(format on save)을 끄는 방법을 단계별로 안내. 프로젝트의 `.vscode/settings.json`에 `"[markdown]": { "editor.formatOnSave": false }`를 넣는 방법도 함께 제안.
- (깨진 두 곳은 2026-10-14 문서 나누기 때 Claude가 `Docs/기획/07_아트_성능_모바일_출시.md`에서 이미 고침)
- 언제: 다음 작업을 시작하기 전에 가장 먼저.
- 완료 조건: `개발현황.md`를 저장해도 고친 줄 말고는 바뀌지 않음 (`git diff`로 확인).
- **처리 결과 (Cursor)**:
  - 자동 서식 설정(`formatOnSave`)은 원래 꺼져 있었고 마크다운 확장도 없음. 진짜 원인은 **Cursor 내장 마크다운 편집기의 꾸민 화면(Rich)** — 파일마다 모드를 기억하며(기본은 글자 화면), 예전 문서의 "Ctrl + Shift + V = 미리보기" 안내로 `개발현황.md`가 꾸민 화면으로 바뀌어 있었음. 꾸민 화면은 저장할 때(스스로 저장하기도 함) 문서를 처음부터 다시 써서 번호 목록 `0.`→`1.`, 굵은 글씨 범위, 표, 빈 줄을 바꿈. 꾸민 화면 안에서는 `Ctrl + Shift + V`가 모드 전환이 아니라 붙여넣기로 동작.
  - 조치: 탭 오른쪽 클릭 → **Edit Markdown**으로 글자 화면 전환(파일마다 기억), `.vscode/settings.json`에 마크다운 서식 끄기·`*.md` 기본 편집기 지정(Git 제외 폴더라 이 PC에만), `개발현황.md` 사용법 문장과 "9. 꼭 기억할 것"에 주의 추가.
  - 확인: 글자 화면에서 한 줄 고쳐 저장 → `git diff --stat` 1줄만 바뀜. 커밋 `d3b89a8`.

**[전달-02] 🔴 Debug.Log 정리 → `GameLog`** (2026-10-14) — ✅ 처리 완료 2026-10-15
- 왜: `Debug.Log`가 29곳. 적 공격·피격·남은 체력·사망·부적 폭발 등 매 타격마다 로그를 찍어서, 귀신 떼가 나오면 성능이 떨어지고(문자열 만들기) Console이 넘쳐 진짜 오류를 놓치기 쉬움.
- 할 일:
  - 정적 클래스 `GameLog` 추가. 함수에 `[System.Diagnostics.Conditional("UNITY_EDITOR")]`와 `[System.Diagnostics.Conditional("DEVELOPMENT_BUILD")]`를 붙여 출시 빌드에서는 호출 자체가 사라지게.
  - 로그 종류별 켜기/끄기 (예: 전투·아이템·지역·저장). 기본값은 **전투만 꺼짐**. 개발자 메뉴(F1)에 "전투 로그 표시" 켜기/끄기 추가.
  - 기존 29곳을 분류해서 바꾸기: 반복 로그 → 전투 종류 / 가끔 일어나는 로그 → 알맞은 종류 / 필요 없는 로그(예: 화면 알림을 그대로 다시 찍는 것)는 삭제. **`Debug.LogWarning`·`Debug.LogError`는 그대로.**
  - 바꾸기 전에 29곳의 목록과 처리 방법을 표로 먼저 보여 주고 사용자 확인.
- 언제: S1-11 2단계 들어가기 전 (작고 독립적인 작업).
- 완료 조건: Console 빨간 오류 0, 전투 로그가 꺼진 상태에서 전투해도 Console이 조용함, F1에서 켜면 로그가 나옴. "9. 꼭 기억할 것"에 "새 로그는 `GameLog` 사용" 규칙 추가, "6. 스크립트 목록"에 `GameLog` 추가.
- **처리 결과 (Cursor)**:
  - 실제로는 30곳(어젯밤 `RegionSettings` 추가분 포함). 사용자 확인한 표대로: 전투 11·아이템 6·지역 3·저장 2로 바꿈, 삭제 2(`PlayerController` "적을 공격합니다!", `NotificationUI`가 화면 알림을 Console에 다시 찍던 것 → 알림 창이 없을 때만 `Debug.LogWarning`), `Editor` 폴더 메뉴 도구 7곳은 `Debug.Log` 그대로.
  - `GameLog`: 머리말 `[전투]`·`[아이템]`·`[지역]`·`[저장]`, 이 프로젝트는 Play 때 스크립트를 다시 불러오지 않으므로(Enter Play Mode Options) Play마다 켜기/끄기를 기본값으로 되돌림.
  - 플레이 테스트: 빨간 오류 0, 끈 상태에서 지역·아이템 로그만, F1 "전투 로그 표시"를 켜면 `[전투]` 로그 나옴. Console의 "JobTempAlloc … leak" 줄은 Unity 내부 메시지로 이 작업과 무관.
  - 문서: "9. 꼭 기억할 것"에 `GameLog` 규칙, `Docs/현재상태.md` 스크립트 표에 `GameLog`.
