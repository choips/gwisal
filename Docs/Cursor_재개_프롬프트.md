# Cursor 개발 재개 프롬프트

> 2026-10-13 작성. 밖에서 Claude와 기획을 크게 업데이트한 뒤, PC의 Cursor로 개발을 다시 시작할 때 사용합니다.

## 0. Cursor를 열기 전에 (사용자가 직접)

1. Unity 에디터를 **닫습니다** (pull 중에 Unity가 파일을 건드리지 않도록).
2. 터미널(PowerShell)에서 프로젝트 폴더로 이동한 뒤:
   ```
   git status
   ```
   - 바뀐 파일이 있으면 먼저 커밋하거나, 필요 없으면 되돌립니다.
3. 최신 내용 받기:
   ```
   git pull origin main
   ```
4. Unity를 다시 열고 **Console 창에 빨간 오류가 없는지** 확인합니다. (이번 업데이트는 문서·엑셀·참고 이미지뿐이라 코드는 바뀌지 않았습니다.)

```
## 3단계: S1 진행 계획 제안 (코드 수정 금지)
S1 항목들은 서로 의존 관계가 있습니다. 문서에 적힌 순서 그대로가 아니라, 안전한 순서로 다시 제안해 주세요.
제가 생각하는 순서는 아래와 같습니다. 더 나은 순서가 있으면 이유와 함께 알려 주세요.

  1. Git LFS 설정 (`.gitattributes`) — 에셋을 넣기 전에
  2. Input Actions 전환 (행동 단위 + 게임패드 대비)
  3. 오브젝트 풀링
  4. 스킬 구조 분리 (`PlayerController`에서 부적 투사체·부적 폭발 분리)
  5. 능력치 시스템 (`StatType`·`StatModifier`·`CharacterStats`·`DamageCalculator`·`BalanceConfig`)
  6. 적 정보 데이터 분리 (`EnemyData`) — 능력치 시스템 위에
  7. 아이템 데이터 구조 개편 + 세이브 형식 버전 3 (계정 공용 / 캐릭터별 분리)
  8. Unity Localization 패키지 도입
  9. 지역 = 씬 하나 구조
  10. 스토리 지역용 고정 배치
  11. 지역 이동 시 자동 저장 / 이어하기
  12. 개발자 UI 기본형 (F1)
  (최소 사양 기기 정하기는 제가 직접 합니다)

각 항목마다 아래를 적어 주세요.
- 바뀌는 스크립트와 새로 만드는 스크립트
- 제가 Unity 에디터에서 해야 할 일 (메뉴 위치, 클릭할 버튼까지)
- 위험한 점 (기존 기능이 깨질 수 있는 곳)
- 큰 항목(Input Actions, 능력치 시스템, 아이템 구조)은 **작은 단계로 쪼갠 계획**
  (각 단계가 끝날 때마다 게임이 정상적으로 플레이되어야 함)

계획을 보여 주시면 제가 확인한 뒤 "1번부터 시작해 주세요"라고 하겠습니다.
그 전까지는 코드를 수정하지 마세요.

## 작업할 때 지킬 것 (Unity 오류 방지)
- **한 번에 한 항목, 큰 항목은 한 단계씩.** 단계마다 제가 플레이 테스트하고 "완료"라고 하면 다음으로 갑니다.
- **매 단계가 끝나면 게임이 컴파일되고 플레이 가능해야 합니다.** Console에 빨간 오류가 남은 채로 다음 단계로 가지 않습니다.
- **기존 기능은 새 구조가 동작하는 걸 확인한 뒤에 지웁니다.** 옛 코드와 새 코드가 잠깐 함께 있어도 괜찮습니다.
- **Inspector에 연결된 필드 이름을 바꾸지 마세요.** 꼭 바꿔야 하면 `[FormerlySerializedAs("옛이름")]`을 붙여 연결이 끊기지 않게 합니다.
- **스크립트 파일 이름과 클래스 이름을 함께 유지**하고, 파일을 옮기거나 이름을 바꿀 때는 `.meta` 파일도 함께 다룹니다 (가능하면 Unity 안에서 옮기도록 안내해 주세요).
- **세이브 형식을 바꿀 때는 버전 번호를 올리고**, 옛 세이브도 불러올 수 있게(또는 안전하게 무시하게) 합니다.
- **enum에 새 값은 맨 뒤에만** 추가합니다 (세이브에 번호로 저장됨).
- **새 Input System 전용**입니다. `Input.GetKeyDown` 같은 옛 방식은 쓰지 않습니다.
- 한글 TextMeshPro는 `NotoSansKR-Regular SDF`를 씁니다.
- 매 프레임 도는 곳(`Update`)에서 `new`, 문자열 합치기, `Find`/`FindFirstObjectByType`, `GetComponent`를 하지 않습니다.
- 마우스 올리기(hover)로만 볼 수 있는 기능을 새로 만들지 않습니다.
- 코드 주석은 한국어, 변수·함수 이름은 영어입니다.
- 패키지(Input System 설정, Localization 등)를 설치하거나 Project Settings를 바꿀 때는 **제가 직접 할 수 있게 단계별로 안내**해 주세요.
- 큰 구조 변경(Input Actions, 능력치 시스템, 아이템 구조, 세이브)을 시작하기 전에는 **Git 커밋으로 백업**하자고 먼저 알려 주세요.
- 작업이 끝날 때마다 `개발현황.md`를 갱신합니다 (`.cursor/rules/dev-status.mdc` 규칙). 백로그 항목을 체크할 때는 그 항목만 바꾸고, 기획 섹션은 제가 요청할 때만 고칩니다.
```

## 2. 이후 작업할 때 쓰는 짧은 프롬프트

계획을 확인한 뒤, 작업을 시작하거나 다음 단계로 넘어갈 때 씁니다.

**작업 시작**
```
개발현황.md의 "0. AI 작업 안내"와 "9. 꼭 기억할 것"을 지키면서,
백로그 S1의 [항목 이름]을 진행해 주세요.
관련 기획은 개발현황.md의 [섹션 이름] 섹션을 참고해 주세요.
큰 작업이면 먼저 단계별 계획을 보여 주고, 제가 확인한 뒤 1단계부터 진행해 주세요.
각 단계가 끝나면 제가 할 에디터 설정과 플레이 테스트 방법을 알려 주세요.
```

**단계 완료 후**
```
완료했습니다. Console에 오류 없고 플레이 테스트도 정상입니다.
개발현황.md를 갱신하고 커밋·푸시한 뒤, 다음 단계로 넘어가 주세요.
```

**오류가 났을 때**
```
Console에 아래 오류가 납니다. 원인을 먼저 설명하고, 고칠 방법을 알려 주세요.
기존에 동작하던 기능은 그대로 유지해야 합니다.
[오류 메시지 붙여 넣기]
```

**새 채팅을 열었을 때** (대화가 길어져 새로 시작할 때)
```
개발현황.md의 "0. AI 작업 안내", "9. 꼭 기억할 것", "2. 지금 진행 중", "4. 백로그"를 읽고,
지금 진행 중인 작업과 다음 할 일을 요약해 주세요. 코드는 아직 수정하지 마세요.
```
